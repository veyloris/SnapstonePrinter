## Architecture decision

Keep the single-module app, existing Compose screen, pure Kotlin slip planner, Canvas renderer, and FileProvider sharing. Fix each defect at the owning boundary and create one feature PR per executor pass. Use committed response fixtures and synthetic image inputs for reproducibility; prohibit runtime Scryfall calls in routine tests.

Separate card identity used by the UI/history from a face's printed fields. Keep existing raw API property naming to minimize migration noise. Use nullable strings for loyalty/defense because printed statistics are text, not necessarily integer arithmetic.

Resize art before tone mapping/dithering and enforce a prepared-art composition contract. Preserve antialiased text separately: the artifact's art pixels must be binary, but the entire bitmap is not required to be a binary-valued image.

For later state work, use explicit generation/render revisions and injected renderer/downloader/export adapters, rather than a broad architecture rewrite or tests that only assert a helper's own bookkeeping. Keep bitmaps in session memory; do not persist them in saved state.

### Step 4 — history tracks the latest completed preview

Scope ViewModel/session state, small renderer/downloader interfaces, and emulator tests with controlled suspended fakes. Add `interface ArtSource { suspend fun fetch(url: String): ArtResult }` implemented by `ArtDownloader`; add `interface SlipRenderer { suspend fun render(plan: List<SlipContent>, art: List<Bitmap?>, contrast: Float, brightness: Float): List<PrintSlip> }` with default implementation owning the Default dispatcher and Step 3 preparation. Inject both through optional constructor arguments preserving production construction; inject no Activity context.

Give every new pull a monotonic session-local Long ID and every render request a revision; retain and cancel the current generation and redither jobs. Store the current pull ID in state. On starting a pull, invalidate prior revisions synchronously, clear current plan/source/current ID, set loading immediately, cancel old work, and prohibit stale completions/errors from changing state. On tone input, mark redithering immediately (including debounce), capture immutable plan/art/tone/IDs, and apply completion only if pull ID+revision still current. Rethrow `CancellationException` before ordinary exception handlers. Only the current request may clear loading/redither flags.

On initial completed generation insert history under its new ID. On completed redither atomically replace both current slips and the matching history entry's slips, without inserting, reordering, or changing unrelated entries. Reprint lookup must resolve `entry.id` against current history at action time; stale/evicted IDs are rejected with a visible error rather than printing a stale passed object. Keep successful history snapshots immutable by replacing bitmap/list references, never mutating reused bitmaps. History remains capped at existing MAX_HISTORY and in-memory only.

Set `canPrint` false while loading or redithering. `printCurrentCard` must enforce the same check, not rely on button state. Allow reprinting a different completed history entry while the current card is loading, subject to the later dispatch job guard. Explicit contract: the most recently completed visible preview is the stored reprint; unfinished tone edits are not printable until completion. If redither fails, retain previous preview/history and report the failure rather than pretending the desired tone completed.
